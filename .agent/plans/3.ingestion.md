# Plan 3: Document Ingestion (Module 2, part 1 of 2)

⚠️ **Medium**: Single-pass is realistic, but it touches four Supabase features (pgvector, Storage, RLS, Realtime), FastAPI and React at once. The phases end at working checkpoints, so a stalled pass can resume at the next phase. Part 2 (retrieval in chat) is `.agent/plans/4.retrieval-tool.md` and depends on this plan.

## Goal

A signed-in user drags `.txt` or `.md` files onto a Documents page. Each file is stored in Supabase Storage, split into chunks, embedded and saved to pgvector. The status (`pending` → `processing` → `ready` / `error`) updates live in the UI through Supabase Realtime. The user can delete a document, which also removes its chunks and its stored file. Every table and the storage bucket are RLS-scoped to the owner.

## Out of Scope

- Using the chunks in chat (plan 4)
- Deduplication and change detection: uploading the same file twice creates two documents (Module 3)
- Metadata extraction (Module 4)
- PDF, DOCX and HTML parsing (Module 5). Module 2 accepts `.txt`, `.md` and `.markdown` only.
- Background job queue or worker process. Processing runs in FastAPI `BackgroundTasks`.

## Key Decisions

1. **Embeddings:** `openai/text-embedding-3-small` through OpenRouter, using the same `openai` SDK client as chat (`base_url` = OpenRouter, wrapped with `wrap_openai` so LangSmith traces it). It returns 1536 dimensions, so the column is `vector(1536)`, which fits pgvector's 2000-dim HNSW limit. Configured with `EMBEDDING_MODEL` and `EMBEDDING_DIMENSIONS`. Changing the model later means a new migration plus re-embedding every document.
2. **Upload path: frontend → FastAPI → Storage.** The browser POSTs `multipart/form-data` to `/api/documents`. FastAPI validates the file, inserts the `documents` row, uploads the bytes to Storage with the user's RLS client, returns `201`, and then processes the file in a `BackgroundTasks` job. Uploading directly from the browser to Storage was rejected because it splits validation across two places.
3. **Processing works on the bytes already in memory**, not a re-download from Storage. Storage is the record of the original file, for Module 3 and later.
4. **Background jobs use the user's RLS client** (the request's `CurrentUser.db`). This keeps "no service-role key in the app" intact. Risk: the user's JWT expires after about an hour, which is far longer than processing a 10 MB text file takes.
5. **Chunking:** our own recursive character splitter in `app/services/chunking.py` (no LangChain). It targets `CHUNK_SIZE=1000` characters with `CHUNK_OVERLAP=200`, splitting on `\n\n`, then `\n`, then `. `, then a space, then hard cuts. Both values come from env.
6. **Embedding batches:** 64 chunks per API call (`EMBEDDING_BATCH_SIZE`). All chunks are embedded first and then inserted, so a failed embedding call leaves no partial chunks behind.
7. **Status is a column on `documents`** (`pending | processing | ready | error`, plus an `error` text column). The frontend subscribes to Realtime `postgres_changes` on `documents`. Realtime respects RLS, so each user only receives their own rows.
8. **Storage layout:** a private bucket named `documents` with paths `{user_id}/{document_id}/{filename}`. Storage RLS checks that the first folder equals `auth.uid()`.
9. **Grants:** every new table gets explicit grants to `authenticated` (the lesson from `002_grants.sql`).
10. **Limits:** `MAX_UPLOAD_MB=10`. The file must decode as UTF-8 (with `utf-8-sig` so a BOM is stripped). An empty file is rejected with `400`.

## Phase A: Database

### Task A1: Migration `003_documents.sql`

```sql
create extension if not exists vector with schema extensions;

create table public.documents (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null default auth.uid() references auth.users(id) on delete cascade,
  filename text not null,
  storage_path text,
  mime_type text,
  size_bytes bigint not null,
  status text not null default 'pending'
    check (status in ('pending', 'processing', 'ready', 'error')),
  error text,
  chunk_count int not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table public.chunks (
  id uuid primary key default gen_random_uuid(),
  document_id uuid not null references public.documents(id) on delete cascade,
  user_id uuid not null default auth.uid() references auth.users(id) on delete cascade,
  chunk_index int not null,
  content text not null,
  embedding extensions.vector(1536) not null,
  created_at timestamptz not null default now(),
  unique (document_id, chunk_index)
);

create index on public.documents (user_id, created_at desc);
create index on public.chunks using hnsw (embedding extensions.vector_cosine_ops);

alter table public.documents enable row level security;
alter table public.chunks enable row level security;

create policy "own documents" on public.documents
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

create policy "own chunks" on public.chunks
  for all using (auth.uid() = user_id)
  with check (
    auth.uid() = user_id
    and exists (select 1 from public.documents d where d.id = document_id and d.user_id = auth.uid())
  );

grant select, insert, update, delete on public.documents to authenticated;
grant select, insert, update, delete on public.chunks to authenticated;

-- Realtime status updates for the ingestion UI
alter publication supabase_realtime add table public.documents;

-- Private storage bucket, one folder per user
insert into storage.buckets (id, name, public)
values ('documents', 'documents', false)
on conflict (id) do nothing;

create policy "own files read" on storage.objects for select to authenticated
  using (bucket_id = 'documents' and (storage.foldername(name))[1] = auth.uid()::text);
create policy "own files insert" on storage.objects for insert to authenticated
  with check (bucket_id = 'documents' and (storage.foldername(name))[1] = auth.uid()::text);
create policy "own files delete" on storage.objects for delete to authenticated
  using (bucket_id = 'documents' and (storage.foldername(name))[1] = auth.uid()::text);
```

Apply it with `backend/venv/Scripts/python backend/scripts/apply_migrations.py 003_documents.sql`.

**Validate:** with psycopg, run these checks:
- `pg_tables` shows `documents` and `chunks` with `rowsecurity = true`.
- `select extname from pg_extension where extname = 'vector'` returns one row.
- `select 1 from pg_publication_tables where pubname = 'supabase_realtime' and tablename = 'documents'` returns one row.
- `select public from storage.buckets where id = 'documents'` returns `false`.
- `pg_policies` lists the three `storage.objects` policies.

**Checkpoint A:** schema, bucket and policies exist.

### Task B2: Chunking service

`app/services/chunking.py`:

```python
SEPARATORS = ["\n\n", "\n", ". ", " ", ""]

def chunk_text(text: str, size: int, overlap: int) -> list[str]:
    """Recursive split: try coarse separators first, merge pieces up to `size`,
    carry `overlap` characters of the previous chunk into the next one."""
```

Rules:
- Normalise `\r\n` to `\n`.
- Strip the input. Empty or whitespace-only input returns `[]`.
- No chunk is longer than `size`.
- Pieces longer than `size` are split recursively with the next separator. `""` means a hard cut every `size` characters.
- Overlap is taken from the end of the previous chunk, snapped forward to the next whitespace so words aren't cut.
- Raise `ValueError` if `overlap >= size`.

**Validate:** `tests/test_chunking.py` checks:
- Empty or whitespace input gives `[]`.
- Short text gives one chunk equal to the stripped input.
- 5,000 characters of paragraphs produce chunks that are all `<= size`.
- Consecutive chunks share overlapping text.
- A single 3,000-character word is hard-cut into `<= size` pieces.
- Paragraph boundaries are preferred: two 400-character paragraphs with `size=1000` come out as one chunk containing both.
- `overlap >= size` raises an error.

### Task B3: Embeddings service

`app/services/embeddings.py`:
- `embed_texts(texts: list[str]) -> list[list[float]]` calls `llm.get_client().embeddings.create(model=EMBEDDING_MODEL, input=batch)` for each batch of `EMBEDDING_BATCH_SIZE`.
- It keeps the input order, sorting each response by `data[i].index`.
- It raises `ValueError` if any vector's length isn't `EMBEDDING_DIMENSIONS`.
- It is decorated with `@traceable(name="embed_texts", run_type="embedding")`.

**Validate:**
- `tests/test_embeddings.py` with a fake client checks three things: 130 texts with batch size 64 produce 3 calls of 64, 64 and 2; output order matches input even when the fake returns `data` shuffled; a wrong dimension raises an error.
- Live: `embed_texts(["hello"])` returns one vector of length 1536. If OpenRouter refuses because of the free tier, stop and ask the user to add credit.

### Task B4: Ingestion service

`app/services/ingestion.py`:

```python
def process_document(db: Client, document_id: str, user_id: str, text: str) -> None:
```

1. Set the status to `processing` and touch `updated_at`.
2. Run `chunk_text(text, CHUNK_SIZE, CHUNK_OVERLAP)`. If it returns nothing, mark the document `error` with "No text content".
3. Run `embed_texts(chunks)`.
4. Insert all chunks in one `insert([...])`. Each row has `document_id`, `user_id`, `chunk_index`, `content` and `embedding`, where `embedding` is passed as a Python list (PostgREST casts the JSON array to `vector`). If a single insert of a large document fails on payload size, insert in batches of 100.
5. Set the status to `ready`, set `chunk_count`, and touch `updated_at`.
6. On any exception: log it, then set the status to `error` with `str(exc)[:500]`.
   - Delete any chunks already inserted for this document, so a partial insert never leaves stray rows.
   - Never re-raise, because it's a background task.
7. Decorate it with `@traceable(name="process_document")`.

**Validate:** in `tests/test_documents.py`, mock `db`, `chunk_text` and `embed_texts`:
- Success path: the status updates are `processing` then `ready`, and the inserted rows have the right indices.
- If embedding raises: the status ends as `error`, the error text is set, and no chunk insert happens.

### Task B5: Documents router

`app/routers/documents.py`, prefix `/api/documents`. Every route uses `get_current_user`.

| Method | Path | Behaviour |
|--------|------|-----------|
| POST | `` | Takes `file: UploadFile`. Rejects with `400` if the extension isn't `.txt`, `.md` or `.markdown`, if the file is larger than `MAX_UPLOAD_MB` (`413`), if it isn't valid UTF-8, or if it's empty. Otherwise it inserts a `documents` row (`status=pending`, `filename`, `mime_type`, `size_bytes`), uploads to Storage at `{user_id}/{doc_id}/{filename}`, sets `storage_path`, schedules `process_document(user.db, doc_id, user.user_id, text)` with `BackgroundTasks`, and returns `201` with the `Document`. If the Storage upload fails, it deletes the row and returns `502`. |
| GET | `` | The user's documents, newest first. |
| DELETE | `/{id}` | Loads the row (`404` if it isn't visible), removes the Storage object (logging any failure, but carrying on), then deletes the row so chunks cascade. Returns `204`. |

- Sanitise the filename used in the storage path: keep only `[A-Za-z0-9._-]` and replace everything else with `_`. Store the original filename on the row for display.
- `models.py` gets `Document` with these fields: `id`, `filename`, `mime_type`, `size_bytes`, `status`, `error`, `chunk_count`, `created_at` and `updated_at`.
- Register the router in `main.py`.

**Validate:** `tests/test_documents.py`, using `TestClient` with an overridden user and a `MagicMock` db:
- Uploading `.pdf` returns `400`.
- An empty file returns `400`.
- Invalid UTF-8 bytes return `400`.
- A file larger than the limit returns `413` (patch `MAX_UPLOAD_MB` to a tiny value).
- A valid `.md` returns `201`, uploads to the expected storage path, and adds `process_document` to the background tasks (patch it to a recorder).
- `DELETE` on a missing id returns `404`.

### Task C2: `useDocuments` hook with Realtime

`hooks/useDocuments.ts`:
- Load once with `listDocuments()`.
- Subscribe with `supabase.channel('documents-' + userId).on('postgres_changes', { event: '*', schema: 'public', table: 'documents', filter: \`user_id=eq.${userId}\` }, handler).subscribe()`.

- Unsubscribe with `supabase.removeChannel` on unmount.
- Return `{ documents, upload, remove, error }`.

Realtime rows contain every column, including ones the API model leaves out. Map them to `Document` and ignore `storage_path`.

## Risks / Notes

- **PostgREST vector input:** passing the embedding as a JSON array normally casts to `vector`. If the insert fails with a type error, send it as the string `"[" + ",".join(map(str, v)) + "]"` instead.
- **Realtime + RLS:** if no events arrive, check that the table is in the `supabase_realtime` publication and that the frontend client has a session. supabase-js passes the access token to Realtime automatically.
- **Free-tier key:** embedding calls may return `402` or `403` until credit is added. Ingestion then marks the document `error` with that message, which is the correct behaviour.
- **Background task + reload:** `uvicorn --reload` restarting mid-ingestion leaves a document stuck in `processing`. That's acceptable for dev; Module 3's record manager can add a retry.
- **Windows:** the venv binaries are under `venv/Scripts/`.
