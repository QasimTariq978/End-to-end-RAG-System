# Plan 2: Switch LLM to OpenRouter (stateless completions)

✅ **Simple**: Single-pass executable. The change touches one service, one router, the config, and the tests. The SSE contract with the frontend (`delta` / `tool` / `done` / `error`) stays the same, so the frontend doesn't change.

## Why

OpenAI credits ran out, and Module 2 moves to OpenRouter anyway. This brings Module 2's LLM layer forward: free OpenRouter models through Chat Completions, with chat history stored by us and sent on every request.

## Trade-off

The OpenAI-managed `file_search` and vector store go away. Chat works, but answers don't come from documents until Module 2 builds its own retrieval (pgvector). `.agent/plans/1.app-shell.md` stays as the historical record. Anything it says about Conversations, Responses or file_search is replaced by this plan.

## Prerequisites (user)

| Item | Where |
|------|-------|
| `OPENROUTER_API_KEY` in `backend/.env` | openrouter.ai → Keys (free account, no card needed) |
| `SUPABASE_DB_URL` in `backend/.env` (only for running migrations from the CLI) | Supabase → **Connect** → Session pooler URI, with the DB password filled in |

## Key Decisions

1. **Client:** the `openai` SDK with `base_url=https://openrouter.ai/api/v1`, still wrapped with `langsmith.wrappers.wrap_openai`. No new LLM dependency.
2. **Model:** the default is `OPENROUTER_MODEL=openrouter/free`. That's OpenRouter's router across currently available free models, so it survives individual free models being retired. You can override it with a fixed `...:free` model ID.
3. **History:** before each turn, load the thread's most recent `HISTORY_LIMIT = 50` messages from Supabase (through the RLS client), oldest first. Send them as `[system, ...history, user]`. Every request is stateless.
4. **Schema:** migration `001` was never applied, so edit it in place and drop `openai_conversation_id`. No second migration.
5. **Migrations runner:** `backend/scripts/apply_migrations.py` uses `psycopg` and `SUPABASE_DB_URL`, and applies every `supabase/migrations/*.sql` file in order, each in its own transaction. It has no tracking table yet, so run each file once.

## Tasks

### T1 Config + env
- `app/config.py`: remove the `OPENAI_*` settings. Add `OPENROUTER_API_KEY`, `OPENROUTER_MODEL="openrouter/free"`, `OPENROUTER_BASE_URL="https://openrouter.ai/api/v1"`, and `SUPABASE_DB_URL=""`.
- `backend/.env.example`: same keys.
- **Validate:** `pytest` collects without import errors.

### T2 LLM service
- `app/services/llm.py`:
  - `build_messages(history, user_text) -> list[dict]` (system prompt + history + user).
  - `stream_reply(messages)` calls `chat.completions.create(model=..., messages=..., stream=True)` and yields:
    - `("delta", {"text"})` for each non-empty `choices[0].delta.content`
    - `("completed", {})` once the stream ends normally
    - `("error", {"message"})` if a chunk carries an `error` field. OpenRouter reports mid-stream failures this way.
  - Remove `ensure_conversation` and the file_search instructions.
- **Validate:** `tests/test_llm.py` covers message ordering, the system prompt position, and the model/base URL coming from settings.

### T3 Chat endpoint
- `app/routers/chat.py`:
  - Drop the conversation step.
  - Load history (`order created_at desc, limit 50`, then reversed) *before* inserting the new user message.
  - Pass `build_messages(history, content)` to `stream_reply`.
  - Persistence and SSE events stay as they are.
- **Validate:** `tests/test_sse.py` is updated and passes. It asserts that the history is passed to the LLM in order.

### T4 Migration
- Remove `openai_conversation_id` from `001_threads_messages.sql`.
- Add `scripts/apply_migrations.py`, and add `psycopg[binary]` to `requirements.txt`.
- **Validate:** after running the script, `GET /rest/v1/threads` with the anon key returns `200 []` instead of `PGRST205`.

### T5 Live check
- Start uvicorn. Sign up a test user through Supabase Auth. Create a thread, then POST a message with `curl -N`.
- **Validate:**
  - The stream has `delta` events, then `done`.
  - A second message referring to the first ("what did I just say?") is answered correctly, which proves history is being sent.
  - The run shows up in LangSmith.

- **Validate:** the README no longer tells the user to get an OpenAI key or a vector store.
